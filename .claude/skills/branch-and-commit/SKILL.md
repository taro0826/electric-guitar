# ブランチを切り、コミットする

## ブランチ

- `main` に直接pushしない。
- できるだけ最新の `main` から `feature/<内容>` のブランチを切る（issue番号は不要）。

```bash
git switch main && git pull
git switch -c feature/<内容>
```

## コミット

- メッセージの先頭に接頭辞を付ける。

  | 接頭辞 | 用途 |
  | --- | --- |
  | `[add]` | 機能・ファイルの追加 |
  | `[update]` | 既存機能の変更・改善 |
  | `[fix]` | 不具合の修正 |
  | `[refactor]` | 動作を変えない整理 |
  | `[doc]` | ドキュメントの変更 |

  例: `[add] 距離センサーの値を取得する処理を追加`

- 1コミットは、意味のある動作確認ができるまとまりにする。大きすぎるコミットは避ける。
- コミットごとにビルドを通す必要はない。途中でビルドが失敗しても、後続のコミットで直っていればよい。
